# План этапа C: безопасность и понятность (FAQ родителей ×10, уроки 5–7 ×10)

Протокол: docs/CONTENT-REVIEW.md. Эталон смысла — RU. Один этап = один промт.
Каждый этап кончается отчётом: что сделано, что проверено (реально запущено),
что не удалось и почему.

## Принципы, на которых стоит план

Google Search Central (по памяти, перепроверить по оригиналу, когда откроют WebFetch):
- «Helpful, reliable, people-first content»: страница пишется для человека, а
  не под поиск; видно, кто написал, как сделано и зачем. Отсюда — честные
  источники и отсутствие обещаний сверх страницы.
- E-E-A-T: опыт, экспертиза, авторитетность, доверие. Для темы детей и
  здоровья доверие важнее всего: каждое утверждение — с первоисточником.
- Структурированные данные (FAQPage JSON-LD) обязаны совпадать с видимым
  текстом. С 2023 г. FAQ-сниппеты в выдаче показываются в основном сайтам
  государства и здравоохранения — разметку держим ради точности, а не ради
  «звёздочек».
- Текст, сделанный с помощью ИИ, допустим, если он полезен и точен; массовая
  генерация ради позиций — нарушение. Отсюда — проверка каждого языка.

Anthropic, практика работы с Claude Code (по памяти, перепроверить):
- Сначала исследовать и прочитать, потом план, потом правка, потом проверка.
- Давать проверяемую цель: тест, который падает на старом тексте.
- Большие задачи — по шагам, с чек-листом в файле; не одним огромным правкой.
- Ясная роль и конкретные критерии в промте; примеры «плохо → хорошо».

## Этапы и промты

### C1. FAQ RU — разбор по ролям (без правок)
> Прочитай js/parents-faq/ru.js целиком. Пройди этапы 0–5 docs/CONTENT-REVIEW.md
> по очереди, роль за ролью. Каждое утверждение с исследованием, законом или
> цифрой сверь с реестром tools/articles/sources.mjs и источниками в data/ru.js;
> нет в реестре — «не подтверждено», не выдумывать. Ищи: противоречия между
> ответами и с нашими же источниками, дубли вопросов, преувеличения, род
> ребёнка, советы, которые просят ребёнка пользоваться чат-ботом младше
> возраста из источника. Итог — таблица находок docs/review/faq-ru.md
> (где → что не так → как исправить → чем проверено).

### C2. FAQ RU — правка по таблице
> Внеси правки из docs/review/faq-ru.md в js/parents-faq/ru.js. Ничего сверх
> таблицы. Для каждого класса ошибок — автотест в tests/ (падает на старом
> тексте): например, «чат-боты с 8 лет» при источнике «13 лет», дубль вопроса.

### C3. FAQ — 9 языков по эталону
> По одному языку за шаг (en de es fr hi id pt tr vi): перенеси смысл
> исправленного RU, сохранив местные примеры (голосовые помощники и сервисы
> страны, см. tests/locale.test.mjs). Нейтральный род, обращение по нормам
> языка (de: Sie взрослому; fr: неразрывные пробелы). Структура — как у RU
> (tests/parity.test.mjs). Без «проверено носителем».

### C4. QA
> `node tools/gen-entry.mjs` (FAQ встроен в главные и JSON-LD), затем
> `node tools/build.mjs --check` и `node --test "tests/**/*.test.mjs"` — 0 fail.
> Ветка → PR с таблицей находок; ждать зелёный CI (build, tests, e2e,
> Lighthouse 100). Чинить код/текст, не ослаблять тесты.

### C5. Выпуск
> Только по «МЕРЖ» владельца: merge → `gh run watch` → deployments success →
> живые ru.html и vi.html содержат новый текст FAQ.

### C6–C10. Уроки 5–7 — то же самое
> C6 разбор RU уроков возраста 5–7 (data/ru.js, tiny) по этапам 1–5 →
> docs/review/lessons-5-7-ru.md; C7 правка RU + тесты; C8 9 языков; C9 QA
> (gen-lessons, build --check, тесты, e2e); C10 выпуск по «МЕРЖ».
