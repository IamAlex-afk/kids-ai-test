# Статьи из первоисточников — постановка задачи и этапы

Черновик 2026-10-28. Правки текстов идут по `docs/CONTENT-REVIEW.md`. Эталон
смысла — RU.

## Задача
Раздел «Статьи» на сайте. Это короткие объяснительные материалы об ИИ для
семьи: для ребёнка (по 4 возрастам) и для взрослого. В каждой статье
собрано, что говорят **первоисточники**: исследования, официальные документы,
отчёты организаций. Из этого делается **явно помеченный вывод сайта**.
Отдельно идёт лента «Свежее»: проверенные новости, которые важны семье.

Пример формы — новостной блок проекта GameAccountValue (только как образец
структуры, код и файлы не переносятся): дата → что произошло (факт) →
«что нового» → «что это значит» (вывод) → блок «источник».

## Что статьёй НЕ является
- Не пересказ СМИ. Статья в СМИ — только указатель на первоисточник, не
  доказательство.
- Не копия чужого текста: свой пересказ и короткие цитаты со ссылкой.
- Не страшилка и не реклама сервисов. Не мнение, выданное за факт.

## Правила (проверяются тестами, где можно)
1. **Каждое утверждение → источник.** В данных хранятся: id источника,
   короткая цитата из оригинала и место (раздел/страница). Утверждение без
   источника не собирается (тест).
2. **Факт и вывод разделены.** У вывода метка «Наш вывод» и уровень
   уверенности: «доказано исследованиями» / «есть данные» / «мнение
   экспертов» / «пока неизвестно».
3. **Даты.** У статьи есть дата публикации и дата последней проверки. Через
   12 месяцев статья помечается «перепроверить» (тест в CI).
4. **Ссылки живые.** `links.yml` проверяет и источники статей. 404 → задача на
   замену, ничего не удаляется автоматически.
5. **Адаптация, а не перевод.** Примеры сервисов и источники должны быть
   доступны и законны в стране языка. Местные законы — свои для каждой страны.
6. **Возраст.** 5–7 — только вместе со взрослым, без новостей. 8–10 — одна
   мысль и один пример. 11–13 — как проверить. 14+ — ограничения, последствия,
   кто получает данные. Блок «Для взрослого» есть везде.
7. **Приватность.** Без регистрации, аналитики, рекламы, сбора ответов.
   CSP не ослаблять.
8. **Честность.** Не писать «проверено носителем/педагогом», если этого не
   было.

## Структура (предложение)
```
tools/articles/<slug>.mjs        данные статьи: sources[], claims[], conclusions[], ages, тексты × 10 языков
tools/articles/sources.mjs       общий реестр источников: id, url, title, publisher, date, type, quote, locator
tools/gen-articles.mjs           генератор (как gen-lessons): страницы + каталог + sitemap; --check
articles/<lang>/index.html       каталог статей языка
articles/<lang>/<slug>.html      статья: факты → «наш вывод» → для взрослого → источники
css/article.css                  стили (в стиле уроков)
tests/articles.test.mjs          у каждого утверждения есть источник+цитата, ключи 10 языков, даты, возраст
```
SEO: hreflang между языками, JSON-LD `Article` с `citation`, отдельный раздел в
sitemap. Lighthouse: A11y/BP/SEO = 100 (порог уже в CI).

## Этапы
| # | Этап | Результат | Выпуск |
|---|---|---|---|
| 0 | Аудит адаптации языков | Таблица: где пример/источник не подходит стране (напр. VI: Alexa/Siri), что взамен | PR на проверку |
| 1 | Формат и генератор | Схема данных, шаблон, тесты, links-check видит статьи. 1 пилотная статья RU+EN | PR (технический) |
| 2 | Пилот × 10 языков | Пилот по CONTENT-REVIEW: 4 возраста, блок для взрослого, адаптация по странам | PR на проверку |
| 3 | Пакет тем (5–8) | Как ИИ учится · почему ошибается · дипфейки и проверка · лента рекомендаций · приватность детей · ИИ и домашка · законы (по странам) | по 1–2 статьи на PR |
| 4 | «Свежее» | Ежемесячный дайджест: только официальные публикации (регуляторы, ЮНЕСКО/ЮНИСЕФ, исследовательские группы). Каждый пункт: дата → факт → что значит для семьи → источник. Без автосбора: собираю → PR → проверка | PR раз в месяц |
| 5 | Поддержка | Еженедельно ссылки, метка «перепроверить» через 12 мес., обновление выводов при новых данных | CI + PR |
